## Stage 01 — Python Foundations 🔄

### What I Learned

#### Functions
- Function definition, parameters, return values
- Default parameters and keyword arguments
- `*args` and `**kwargs` — accepting variable arguments
- Scope — local vs global variables
- Type hints — annotating parameters and return types
- Docstrings — Google format (Args, Returns, Raises)
- Input validation and defensive programming
- `logging` module instead of print statements
- `if __name__ == "__main__"` pattern
- Clean function design — one function, one job

#### Object Oriented Programming
- Classes and objects — blueprint vs instance
- `__init__` method — initializing object state
- Instance attributes and methods
- `self` — understanding what it references
- Encapsulation — protecting internal state with `_`
- Inheritance — extending classes with `super()`
- Defensive design — objects protecting their own integrity
- Special methods and class design patterns

#### String Operations
- String indexing and negative indexing
- String slicing — `[start:end:step]`
- Core string methods — `strip()`, `lower()`, `upper()`, `title()`
- Finding and checking — `find()`, `count()`, `startswith()`, `endswith()`
- `split()` and `join()` — the most used pair in data work
- `replace()` — cleaning inconsistent data
- f-strings — modern professional string formatting
- Number formatting — `:.2f`, `:,` for thousands
- Aligned output — `:<20` and `:>10` for reports
- String immutability — always capture the return value
- Real world data cleaning — column name standardization

### Professional Standards Applied
- Type hints on all function parameters and return values
- Google format docstrings on every function and class
- `logging` module for all output instead of `print()`
- Input validation on every function
- `if __name__ == "__main__"` for test execution
- Constants in UPPER_CASE
- Defensive programming — checking edge cases proactively
- Clean naming — descriptive function and variable names

### Tools and Environment Setup
- Python virtual environment (`.venv`)
- VS Code as primary IDE
- Git and GitHub — version control and remote repository
- `.gitignore` — excluding `.venv` and cache files
- `requirements.txt` and `requirements-core.txt`
- CMD as terminal for Windows development
- SSH authentication with GitHub
- Kaggle account setup
- LinkedIn profile updated

### Key Concepts Understood
- Why functions exist — write once, reuse everywhere
- Why OOP exists — blueprint for creating multiple objects
- The difference between object creation and method calls
- What `self` actually means in Python
- Why strings are immutable
- Why `logging` beats `print()` in production code
- Why `.gitignore` matters in professional projects
- Why `requirements.txt` exists and how pip dependencies work
